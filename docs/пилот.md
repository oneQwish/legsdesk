# Пилот на тестовых данных

Пилот проходится на своём компьютере, без сервера компании и без 1С. Данные вымышленные (около 300 дел трёх
юрлиц), но устроены как настоящие: источники расходятся, есть просроченные сроки и сроки на сегодня,
документы без дела, дубли, дела без УИД. Даты считаются от дня загрузки, поэтому пилот выглядит «живым»
в любой день.

## 1. Запуск

Нужен **Docker Desktop** (Windows/macOS) или Docker (Linux), около 3 ГБ на диске.

| Действие | Windows | macOS / Linux |
|---|---|---|
| Запустить (первый раз 3–5 минут: сборка) | `pilot\запустить.bat` | `pilot/запустить.sh` |
| Остановить (данные сохраняются) | `pilot\остановить.bat` | `docker compose -f pilot/docker-compose.yml stop` |
| Начать заново с чистыми данными | `pilot\сбросить.bat`, затем запустить | `pilot/сбросить.sh`, затем запустить |

Откройте **http://localhost:8080**. Пароль у всех — `dev`.

| Логин | Роль | Зачем |
|---|---|---|
| `ivanova`, `sidorova` | юрист | основная работа; у каждой около сотни «своих» дел |
| `petrov` | просмотр | проверить, что без прав юриста ничего нельзя изменить |
| любой другой (например `admin`) | администратор | раздел «Сервисы и API» |

> Режим входа без пароля — только для пилота. На сервере компании вход через AD (см. [администрирование](администрирование.md)).

## 2. Сценарий

Отмечайте результат в последней колонке: ✓ — как ожидалось, ✗ — нет (и запишите замечание, раздел 3).
Пункты можно проходить в любом порядке и в несколько заходов.

### Стол (вход под `ivanova`)

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|
| 1 | Открыть «Стол» | Лента дней на 2 недели: точки сроков по видам, выходные бледнее, слева «просрочено» | |
| 2 | Нажать на день с точками в ленте | Список сроков этого дня | |
| 3 | Посмотреть «Чистый стол» и «Моя неделя» | Число конфликтов и просрочек; серия дней без просрочек | |
| 4 | В стопке «Горят сроки» листать ‹ › | Карточки сменяются; позиция не сбрасывается сама | |
| 5 | Нажать «Разложить» | Карточки раскладываются по столу; Esc собирает обратно | |
| 6 | Стопка «Мои дела» | Только дела, где ответственная — ivanova | |

### Дела и фильтры

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|
| 7 | «Дела» → фильтр «Юрлицо: ГС-Саввино», «Корпус: 401» | Счётчики у остальных фильтров пересчитались; чипы над списком | |
| 8 | Фильтр «Судья» → любой | Только дела этого судьи (в т. ч. где источники называют судью по-разному) | |
| 9 | «Сохранить подборку», выложить на стол | Подборка появилась кнопкой в фильтрах и стопкой на «Столе» | |
| 10 | Переключить «Карточки / Таблица» | Тот же список в двух видах | |
| 11 | `Ctrl K` → «корп 308», «2024», «судья …» | Подсказки фильтров; Enter применяет | |

### Карточка дела

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|
| 12 | Открыть дело с решением | Путь дела (иск → … → исполнение), текущий этап выделен | |
| 13 | Сводка «присуждено от заявленного» | Полоса с процентом и разбивкой по категориям | |
| 14 | Вкладка «Сроки» | Апелляция и вступление в силу посчитаны; «Как посчитано» — статья ГПК и переносы | |
| 15 | Отметить срок «Выполнено» | Срок закрыт; на «Столе» и в ленте дней его больше нет | |
| 16 | «Дата…» — поменять дату срока | Срок помечен «вручную» и больше не пересчитывается | |
| 17 | Вкладка «Хронология» | Акты, сроки и решения на одной оси | |
| 18 | «Ответственный» → `sidorova` | Дело ушло из «Моих дел» ivanova, появилось у sidorova | |

### Конфликты

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|
| 19 | «Конфликты» → клавиши `1`/`2`, `Enter` | Значение принято; конфликт ушёл из очереди, выделен следующий | |
| 20 | «Своё значение» без комментария | Кнопка «Принять» недоступна; Enter тоже не принимает | |
| 21 | Разобрать все конфликты на странице | Подгружаются следующие (не появляется «конфликтов нет», пока они есть) | |
| 22 | В карточке дела решённое поле → «Пересмотреть» | Поле снова спорное | |

### Документы

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|

| 25 | Поиск по тексту документа | Совпадения подсвечены | |

### Дубли и дела без УИД

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|

| 27 | Найти пару (тот же истец и квартира), открыть основное дело → «Слить дубль…» → ID дубля | Номера, значения и история дубля перешли в дело, дубль исчез | |

### Роли и администрирование

| № | Что сделать | Что должно получиться | Итог |
|---|---|---|---|
| 28 | Войти под `petrov` | Всё видно, но решать конфликты, править сроки и сливать дела нельзя | |
| 29 | Войти под `admin` → «Сервисы и API» | Список сервисов, ключи, очередь задач (3 тестовые), пользователи | |
| 30 | «Выгрузка» → XLSX | Файл с решениями юристов (после п. 19 там есть строки) | |
| 31 | «Журнал» | Все ваши действия за пилот, по людям и сервисам | |

### Коннекторы (по желанию, для программиста 1С)

## 3. Замечания

Записывайте сразу, коротко, по одному на строку — так их проще разобрать:

| № пункта | Где (страница, кнопка) | Что ожидали | Что получилось | Важность (мешает / неудобно / идея) |
|---|---|---|---|---|
| | | | | |

Если что-то сломалось — пришлите ещё текст из `docker compose -f pilot/docker-compose.yml logs app --tail=100`.

## 4. Что пилот не проверяет

Вход через AD, обмен с настоящей 1С и sot.db, HTTPS и резервные копии — это проверяется на сервере компании,
когда появится доступ (этап 0 в [плане](план-развития.md)).
