# Коннекторы: обмен данными с любыми системами

Коннектор — это **файл настроек** (`.toml`) и **одна программа**, которая его выполняет:
`connectors/lawdesk_connect.py`. Программировать не нужно: что читать, откуда и куда класть, описывается
в файле настроек. Программа сама проверяет файл и объясняет ошибки по-русски.

## 1. Быстрый старт за 10 минут

1. **Получите ключ.** В рабочем месте: «Сервисы и API» → «Подключить сервис» → имя (например,
   `excel-reports`), отметьте области `read` и `ingest` → «Создать и выдать ключ». Скопируйте ключ —
   он показывается один раз.
2. **Сохраните ключ и адрес.** В папке `connectors` скопируйте `секреты.пример.bat` → `секреты.bat`
   и впишите адрес и ключ. (Linux: `секреты.пример.sh` → `секреты.sh`.)
3. **Возьмите заготовку** под ваш источник из папки `connectors/примеры` (список — в разделе 4),
   скопируйте в `connectors/подключения/` и переименуйте по смыслу.
4. **Поправьте** путь к файлу (или адрес системы) и названия колонок в фигурных скобках `{…}`.
5. **Проверьте** — ничего не отправляется, показывается, что будет отправлено:
   ```
   cd connectors
   секреты.bat
   python lawdesk_connect.py проверить подключения/мой.toml
   ```
6. **Запустите**: `python lawdesk_connect.py запустить подключения/мой.toml`.
7. **Посмотрите результат** в рабочем месте: «Дела» → поиск по номеру; в карточке дела — вкладка
   «Поля и источники», где виден ваш источник.

Повторный запуск безопасен: дела находятся по УИД/номеру, значения — по паре «источник + ключ записи»,
документы — по содержимому файла. Ничего не задваивается.

## 2. Установка

Нужен **Python 3.11 или новее** (без дополнительных пакетов — коннектор использует только стандартную
библиотеку). Проверка: `python --version`.

- Windows: скачать с python.org, при установке отметить «Add python.exe to PATH».
- Скопировать папку `connectors` целиком на компьютер, откуда видны источники (например, сервер 1С или
  рабочий ПК с выгрузками).
- Для `type = "sql"` (PostgreSQL, MS SQL …) дополнительно: `pip install sqlalchemy` и драйвер СУБД.

## 3. Устройство файла настроек

Формат — TOML: разделы в `[квадратных скобках]`, внутри строки `имя = значение`.

```toml
# комментарий — всё после # программа не читает

[connector]                     # обязательный раздел: что это за подключение
name = "Отчёт юристов"          # название — так оно видно в журналах
api_url = "https://lawdesk.company.local"   # адрес рабочего места; переменная LAWDESK_URL (секреты.bat) главнее
api_key_env = "LAWDESK_KEY"     # из какой переменной окружения брать ключ (по умолчанию LAWDESK_KEY)
# api_key_file = "ключ.txt"     # …или из файла с одной строкой-ключом (в git не класть!)
direction = "in"                # in — данные В рабочее место, out — ИЗ рабочего места наружу
# limit = 100                   # обработать только первые N записей (для пробы)
# log_dir = "журналы"           # куда писать журнал (по умолчанию «журналы» рядом с файлом настроек)
# cafile = "корпоративный-ca.pem"   # сертификат вашего УЦ, если HTTPS на внутреннем сертификате
# timeout = 180                 # сколько секунд ждать ответ рабочего места на один пакет
# batch = 500                   # сколько записей отправлять одним пакетом
# retry_delays = [2, 5, 10, 20, 40]   # паузы (с) между повторами при сбое связи; [] — не повторять

[source]                        # откуда читать (для direction = "in")
type = "csv"
path = "данные/дела.csv"

[cases]                         # как из записи получить дело
[observations]                  # какие значения полей отправить
[documents]                     # какие документы загрузить
[calendar]                      # производственный календарь
[maps.имя_латиницей]            # таблицы перевода значений
```

Правила записи, о которые чаще всего спотыкаются:

| Правило | Правильно | Неправильно |
|---|---|---|
| Текст — в кавычках | `name = "Отчёт"` | `name = Отчёт` |
| Русское имя **слева от `=`** — в кавычках | `"УИД" = "{case.uid}"` | `УИД = "{case.uid}"` |
| Имена разделов — латиницей | `[maps.entities]` | `[maps.юрлица]` |
| Путь Windows — через `/` | `path = "D:/выгрузки/дела.csv"` | `path = "D:\выгрузки\дела.csv"` |
| Многострочный текст (SQL) — в тройных кавычках | `query = """SELECT …"""` | |
| Список — в квадратных скобках | `actions = ["value_resolved"]` | |

Опечатку в имени параметра программа поймает и подскажет: «неизвестный параметр «delimeter». Может быть,
«delimiter»?».

## 4. Источники данных `[source]`

| type | Откуда | Заготовка | Обязательно |
|---|---|---|---|
| `csv` | CSV-файл (выгрузка из 1С, Excel, любой программы) | `csv.toml` | `path` |
| `xlsx` | файл Excel | `xlsx.toml` | `path` |
| `json` | JSON-файл | `json.toml` | `path` |
| `folder` | папка с файлами (сканы, PDF писем, документы ФССП) | `папка_документов.toml` | `path` |
| `odata` | стандартный интерфейс OData — **1С** и другие системы | `1с_odata.toml`, `календарь_1с.toml` | `url`, `entity` |
| `http_json` | любой HTTP-сервис, отдающий JSON (в т.ч. HTTP-сервис 1С) | `1с_http.toml` | `url` |
| `sqlite` | база SQLite (например, sot.db конвейера) — только чтение | `sqlite_sot.toml` | `path`, `query` |
| `sql` | PostgreSQL, MS SQL, Oracle … через SQL-запрос | `sql.toml` | `query`, `url_env` |

Посмотреть заготовку: `python lawdesk_connect.py шаблон csv` (без имени — список всех).

### Общие параметры

```toml
[[source.only_if]]              # брать только строки, где…
column = "Статус"
not_in = ["Удалено", "Черновик"]   # …значение НЕ из списка
# in = ["Рассмотрено"]            # …или значение из списка
# not_empty = true                # …или колонка не пустая
```
Условий может быть несколько — каждое в своём блоке `[[source.only_if]]`, все должны выполняться.

### csv
| Параметр | Значение | По умолчанию |
|---|---|---|
| `path` | путь к файлу (от папки файла настроек или полный) | — |
| `encoding` | кодировка: `utf-8-sig` (1С, Excel «CSV UTF-8»), `cp1251` (старые выгрузки) | не указана — UTF-8, а если не читается, то cp1251 (сам) |
| `delimiter` | разделитель колонок | угадывается (`;` или `,`) |

Первая строка файла — заголовки колонок; по ним и обращаемся в шаблонах.

### xlsx
| Параметр | Значение |
|---|---|
| `path` | путь к файлу `.xlsx` (старый `.xls` — сохраните как `.xlsx`) |
| `sheet` | имя листа (по умолчанию первый) |
| `skip_rows` | сколько строк пропустить перед строкой заголовков (шапка отчёта) |
| `date_columns` | колонки с датами — Excel хранит даты числом, здесь они станут `ГГГГ-ММ-ДД` |

### json
`path`; `items_path` — где в файле список записей (через точку: `data.items`). Вложенные поля записи —
через точку в шаблоне: `{суд.код}`.

### folder (папка с файлами)
| Параметр | Значение | По умолчанию |
|---|---|---|
| `path` | папка | — |
| `pattern` | какие файлы: `*.pdf`, `*решение*.pdf` | `*` |
| `recursive` | заходить во вложенные папки | `true` |
| `min_age_minutes` | брать только файлы, не менявшиеся столько минут (сканер мог ещё не дописать файл) | `2` |

Уже загруженные файлы (по `sha256`) запоминаются в `состояние/<название>.отправлено` и при следующих
запусках не закачиваются заново. Чтобы загрузить всё повторно, удалите этот файл.

Для каждого файла доступны колонки: `{файл}` (имя с расширением), `{имя}` (без расширения),
`{расширение}`, `{папка}` (имя папки, где лежит файл), `{путь}`, `{размер}`, `{sha256}`.
Дополнительные сведения кладутся в **файл-спутник**: рядом с `решение.pdf` — `решение.pdf.json`
(или `решение.json`), например `{"уид": "50RS…", "вид": "решение", "дата": "15.03.2027"}` — его поля
становятся колонками. Сами `.json` как документы не загружаются.

### odata (1С и другие системы)
| Параметр | Значение |
|---|---|
| `url` | адрес до `standard.odata`: `http://сервер/база/odata/standard.odata` |
| `entity` | имя объекта: `Catalog_СудебныеДела`, `Document_…`, `InformationRegister_…` |
| `select` | какие поля (через запятую) — ускоряет загрузку |
| `filter` | условие OData: `DeletionMark eq false`, `Год eq 2027` |
| `expand` | раскрыть ссылки, чтобы взять их реквизиты: `expand = "Суд"` → `{Суд.Description}` |
| `orderby` | сортировка |
| `page_size` | сколько записей за запрос (1С — 1000–5000) |
| `user`, `password_env` | пользователь и **имя переменной окружения** с паролем |
| `cafile` | корневой сертификат компании, если 1С опубликована по HTTPS на внутреннем сертификате |

Страницы читаются до первой пустой — даже если 1С отдаёт меньше записей, чем `page_size`, ничего не
потеряется. Если данные в 1С меняются прямо во время чтения, задайте `orderby = "Ref_Key"`.
Временные сбои связи (обрыв, перезапуск, ответы 429/5xx) повторяются автоматически с паузами до ~1,5 минут.

Как опубликовать OData в 1С — [api-для-1с.md, раздел 1](api-для-1с.md#1-опубликовать-odata).

### http_json
| Параметр | Значение |
|---|---|
| `url` | адрес |
| `items_path` | где в ответе список записей (`items`, `data.rows`) |
| `next_path` | где в ответе ссылка на следующую страницу (если сервис постраничный) |
| `page_size`, `offset_param`, `limit_param` | постраничность через параметры `offset/limit` |
| `params` | дополнительные параметры: `params = { since = "2027-01-01" }` |
| `headers` | дополнительные заголовки: `headers = { "X-Token" = "…" }` |
| `user`, `password_env` | Basic-авторизация |
| `timeout` | ожидание ответа, секунд (по умолчанию 120) |

### sqlite / sql
`query` — SQL-запрос; каждая колонка результата становится колонкой для шаблонов (используйте
`AS имя`). SQLite открывается **только на чтение**. Для `sql` строка подключения — в переменной
окружения `url_env` (пример строк — в `sql.toml`). Подключайтесь к копии или пользователем только с
правом чтения.

## 5. Шаблоны значений и фильтры

Значение в настройках — это **шаблон**: текст, в котором `{Колонка}` заменяется значением из записи
источника.

```toml
case_number = "{Номер дела}"                 # просто колонка
court_name = "{Суд} ({Регион})"              # несколько колонок и текст
claim_total = "{Заявлено|money}"             # колонка + фильтр
decision_date = "{Дата|date:%d.%m.%Y}"       # фильтр с параметром
legal_entity = "{Ответчик|trim|map:entities}"   # несколько фильтров подряд
judge = "{Судья|default:не указан}"         # если пусто (или колонки нет) — «не указан»
```

Регистр букв и «ё» в имени колонки не важны: `{уид}` найдёт колонку «УИД».

### Фильтры

| Фильтр | Что делает | Пример |
|---|---|---|
| `trim` | убирает пробелы по краям | ` 2-101/27 ` → `2-101/27` |
| `upper` / `lower` | ВЕРХНИЙ / нижний регистр | |
| `money` | сумма в число с копейками | `1 200 000,50 руб.` → `1200000.50` |
| `kopecks` | копейки в рубли | `12345` → `123.45` |
| `int` | целое число | `12.0` → `12` |
| `date` | дата в `ГГГГ-ММ-ДД`; понимает `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, даты 1С с временем; пустая дата 1С `0001-01-01` → пусто | `15.03.2027` → `2027-03-15` |
| `date:формат` | дата в заданном формате (`%d` день, `%m` месяц, `%Y` год, `%H:%M` время) | `{Д\|date:%Y%m%d}` |
| `digits` | только цифры | `№ 2-101` → `2101` |
| `first` | первое значение из списка через `;` или `,` | `Иванов; Петров` → `Иванов` |
| `replace:что=>на что` | замена текста | `{Дог\|replace:АВт=>АВТ}` |
| `default:значение` | подставить, если пусто **или колонки нет** | `{Трек\|default:}` |
| `bool` | да/нет → `true`/`false` (понимает «Да», «Истина», «1», «+») | |
| `map:имя` | перевод по таблице `[maps.имя]` | см. ниже |

### Таблицы перевода `[maps]`

```toml
[maps.entities]                         # имя таблицы — латиницей
"ООО «Главстрой-Саввино»" = "ГС-Саввино"
"ООО «Главстрой-СПб»" = "ГС-СПб"
"*" = "не определено"                   # для всех остальных значений (если не указать — значение без изменений)
```
Использование: `legal_entity = "{Ответчик|map:entities}"`.

## 6. Что отправлять

В одном файле настроек можно задать один или несколько разделов: `[cases]`, `[observations]`,
`[documents]`, `[calendar]`.

### `[cases]` — дело

Создаёт дело или обновляет найденное (по УИД, иначе по коду суда + номеру).

| Параметр | Что |
|---|---|
| `uid` | УИД дела |
| `court_code` | код суда (по справочнику судов) |
| `court_name` | название суда |
| `case_number` | основной номер дела |
| `aliases` | другие номера через `;` (М-…, прежние 2-…) |
| `legal_entity`, `complex`, `building`, `flat`, `contract_no` | юрлицо, ЖК, корпус, квартира, договор |
| `plaintiffs`, `subject`, `stage`, `status`, `outcome` | истцы, предмет, стадия, статус, исход |
| `responsible` | ответственный юрист (логин) |
| `appeal_flag` | признак обжалования (`{Обжалуется\|bool}`) |

Строка без УИД и без номера пропускается с предупреждением.

> Поля карточки (`plaintiffs`, `outcome` и т. п.) из `[cases]` перезаписываются последним источником.
> Если важно видеть расхождения источников, присылайте значение также в `[observations]` — тогда при
> расхождении появится конфликт.

### `[observations]` — значения полей по источнику

```toml
[observations]
source = "1С"                     # имя источника — так его увидят юристы
source_ref = "{Ref_Key}"          # ключ записи в источнике: повтор обновляет, а не задваивает
# send_empty = false              # отправлять ли пустые значения (по умолчанию — нет)

[observations.fields]             # поле рабочего места = шаблон
judge = "{Судья}"
claim_total = "{Заявлено|money}"
# С цитатой, страницей и ссылкой на документ:
amount_debt = { value = "{Долг|money}", quote = "{Цитата}", page = "{Стр}", document_sha256 = "{sha256}" }
```
Если в файле нет `[cases]`, дело для значений указывается здесь же: `uid = "{УИД}"` или
`court_code = "…"` + `case_number = "…"` (или `case_id`).

**Как выбрать `source_ref`**: значение, которое однозначно определяет запись в источнике и не меняется —
ссылка 1С (`Ref_Key`), номер строки реестра, трек письма, sha256 документа. Если один источник даёт два
разных значения поля для одного дела (два решения) — у них должны быть разные `source_ref`.

### `[documents]` — документы

```toml
[documents]
file = "{путь}"                   # указан — файл загружается в хранилище; не указан — только карточка
filename = "{файл}"
kind = "скан"                     # скан | письмо | иск | возражение | ФССП | прочее
act_type = "{вид}"                # решение | определение … | апелляционное определение | кассационное определение
instance = "первая"               # первая | апелляция | кассация
act_date = "{дата|date}"
motivated_date = "{мотивированное|date}"   # от неё считается срок апелляции
track_no = "{трек|default:}"
text = "{текст|default:}"         # распознанный/цифровой текст, если есть
# signature_file = "{папка}/{имя}.sig"
# storage_backend = "external"    # файл уже лежит в другой системе — не загружать
# docflow_id = "{ИдКарточки}"     # идентификатор карточки в системе документооборота

[documents.case]                  # к какому делу привязать (если в файле нет [cases])
uid = "{уид}"
# court_code = "{код суда}"
# case_number = "{номер}"

[documents.meta]                  # любые дополнительные сведения
delivered_date = "{вручено|date}" # дата вручения заочного решения (для срока отмены)
```
По виду акта и датам **автоматически** считаются процессуальные сроки. Если указанного дела нет,
документ сохраняется непривязанным — его можно привязать вручную в интерфейсе.

### `[calendar]` — производственный календарь

Источник должен содержать **все дни года** (365/366 записей). Ключу нужна область `calendar`.

```toml
[calendar]
date = "{Дата|date}"
day_type = "{ВидДня}"
nonworking_values = ["Суббота", "Воскресенье", "Праздник", "Нерабочий"]
source_name = "1С: регламентированный календарь"
```
Вместо `day_type` можно указать `working = "{Рабочий|bool}"`. После загрузки открытые
автоматические сроки сразу пересчитываются. Загружайте следующий год, как только он утверждён (обычно
осенью).

## 7. Поля дела

Список полей, которые принимает рабочее место:
```
python lawdesk_connect.py поля подключения/мой.toml
```

| Ключ | Поле | Тип |
|---|---|---|
| `court` | Суд | текст |
| `judge` | Судья | текст |
| `decision_date` / `motivated_date` / `effective_date` | дата решения / мотивированного / вступления в силу | дата |
| `outcome`, `subject` | исход, предмет иска | текст |
| `plaintiffs` | истцы (через `;`) | список |
| `defendant` | ответчик (юрлицо) | текст |
| `complex`, `building`, `flat`, `contract_no` | ЖК, корпус, квартира, договор | текст |
| `claim_total` | заявлено всего | сумма |
| `amount_debt`, `amount_penalty`, `amount_fine`, `amount_moral` | долг, неустойка, штраф, моральный вред | сумма |
| `amount_expertise`, `amount_postal`, `amount_representative`, `amount_duty` | экспертиза, почтовые, представитель, госпошлина | сумма |

Новое поле добавляется в `backend/fields.toml` ([администрирование](администрирование.md#7-поля-дела-fieldstoml)).
Неизвестное поле коннектор отправит с предупреждением — оно будет принято как текстовое.

## 8. Выгрузка наружу (`direction = "out"`)

Коннектор читает **ленту изменений** рабочего места с места прошлой остановки и записывает новые события
в файл или отправляет в HTTP-сервис другой системы. Курсор хранится в файле `state_file` и сдвигается
**только после успешной записи** — при сбое ничего не теряется, при повторе ничего не дублируется.
Ключу нужна область `export`.

```toml
[connector]
name = "Решения юристов → 1С"
direction = "out"

[feed]
actions = ["value_resolved"]              # какие события
state_file = "состояние/решения.курсор"   # где хранить курсор
# start_from = 0                          # с какого события начать в первый раз (0 — с начала)

[sink]
type = "csv"                              # csv | json | http
path = "выгрузки/решения_{date}.csv"      # {date} — дата и время запуска
mode = "new"                              # new — новый файл каждый раз; append — дописывать в один файл

[sink.columns]                            # колонки результата (без этого раздела — все поля события)
"УИД" = "{case.uid}"
"Поле" = "{field_label}"
"Значение" = "{value}"
```

Лента читается и записывается **порциями по 500 событий**; после каждой записанной порции курсор
сохраняется. Если запуск прервался (нет связи, выключили компьютер), следующий продолжит с первой
незаписанной порции. Файл курсора пишется так, что обрыв не оставит его пустым; если он всё же пустой
или испорчен, коннектор остановится с объяснением, а не начнёт выгрузку всей истории заново.

При `mode = "new"` без `{date}` в имени: если прошлый файл ещё лежит (1С его не забрала), он **не
затирается** — новый файл получает в имени дату и время.

### События (`actions`)

| Событие | Когда |
|---|---|
| `value_resolved` | юрист разрешил конфликт (выбрал значение) |
| `value_reopened` | решённое поле снова открыто (новое значение источника или вручную) |
| `value_status` | поле стало конфликтным / перестало быть |
| `case_created`, `case_updated`, `case_merged` | дело создано / изменено / слиты дубли |
| `document_created`, `document_updated`, `document_linked` | документ загружен / изменён / привязан к делу |
| `deadline_added`, `deadline_updated` | срок добавлен / изменён (в т.ч. отмечен выполненным) |
| `calendar_loaded`, `export` | загружен календарь / сделана выгрузка |

### Что можно подставлять в колонки

| Шаблон | Значение |
|---|---|
| `{id}`, `{feed_seq}` | номер события (уникален — используйте как ключ на приёмнике) |
| `{action}`, `{ts}`, `{date}` | вид события, время, дата |
| `{actor}`, `{actor_type}` | кто: логин юриста или имя сервиса; `user` / `service` |
| `{field}`, `{field_label}` | ключ и название поля |
| `{value}`, `{previous}` | новое и прежнее значение |
| `{chosen}`, `{note}` | какой источник выбран; комментарий юриста |
| `{case.uid}`, `{case.court_code}`, `{case.court_name}`, `{case.case_number}`, `{case.legal_entity}`, `{case.responsible}`, … | реквизиты дела |
| `{data.…}` | любые сведения события (например, `{data.changes}`) |

Если значения нет (например, у события без дела), ячейка будет пустой — ошибки не будет.

### Приёмник `http`

```toml
[sink]
type = "http"
url = "http://srv-1c/ura/hs/lawdesk/decisions"
method = "POST"
user = "lawdesk_writer"
password_env = "LAWDESK_1C_PASSWORD"
batch = 200              # записей в одном запросе
# envelope = false       # слать просто массив вместо {"source", "connector", "items"}
```
Тело запроса: `{"source": "lawdesk", "connector": "…", "ids": [номера событий], "items": [ … ]}`.
Приёмник должен ответить HTTP 200 и спокойно принимать повтор: после сбоя посреди порции её начало может
прийти второй раз — отличайте повтор по номеру события из `ids` (он же `{id}`). `cafile` — как у источника. Пример приёмника на 1С —
[api-для-1с.md, раздел 5](api-для-1с.md#5-http-сервис-1с-принимающий-решения).

## 9. Запуск по расписанию

Положите рабочие файлы настроек в `connectors/подключения/` — их по очереди выполняет `запуск.bat`
(Windows) или `запуск.sh` (Linux).

**Windows — Планировщик заданий:**
1. «Планировщик заданий» → «Создать задачу».
2. Общие: имя «Рабочее место юриста — обмен», «Выполнять для всех пользователей».
3. Триггеры: «Ежедневно», повторять каждые 30 минут (или 1 час).
4. Действия: «Запуск программы» → `C:\lawdesk\connectors\запуск.bat`, «Рабочая папка»: `C:\lawdesk\connectors`.
5. Параметры: «Не запускать новый экземпляр, если задача уже выполняется».

Даже если два запуска совпали (вручную и по расписанию), одно подключение не выполняется дважды
одновременно: второй запуск пишет «ПРОПУЩЕНО: это подключение уже выполняется» и завершается с кодом 4.

**Linux — cron** (`crontab -e`):
```
*/30 * * * * /opt/lawdesk/connectors/запуск.sh >> /opt/lawdesk/connectors/подключения/журналы/cron.log 2>&1
```

Как часто: источники, которые меняются редко (реестры, отчёты) — раз в сутки; выгрузка решений юристов
и календарь — раз в 15–60 минут / раз в год соответственно.

## 10. Журналы и коды возврата

Каждый запуск пишет журнал в папку `журналы` рядом с файлом настроек (`журналы/<название>.log`):
сколько прочитано и отправлено, предупреждения и ошибки **с номером строки источника** (строка 1 —
первая строка данных после заголовков). Журнал хранится в 5 файлах по 5 МБ, старые удаляются сами.

Если в пакете из 500 строк одна с неверным форматом (например, дата не через `|date`), сервер
отклоняет весь пакет — коннектор сам делит его и отправляет все правильные строки, а про неправильную
пишет «строка N: поле act_date: …».

| Код возврата | Значит |
|---|---|
| 0 | всё хорошо |
| 1 | выполнено, но были проблемы со строками (пропущены, отклонены) — см. журнал |
| 2 | ошибка в файле настроек — ничего не отправлено |
| 3 | нет связи / ошибка доступа (рабочее место или внешняя система) — записанное сохранено, остальное повторится при следующем запуске |
| 4 | это подключение ещё выполняется с прошлого раза — запуск пропущен (не ошибка, если бывает редко) |
| 5 | неожиданная ошибка — в выводе подсказка, подробности для программиста в файле журнала |

`запуск.bat` / `запуск.sh` возвращают наибольший код из всех подключений.

## 11. Частые ошибки

| Сообщение | Причина | Что сделать |
|---|---|---|
| `ошибка в записи файла настроек … Invalid initial character` | русское имя без кавычек слева от `=` или в `[разделе]` | `"УИД" = …`; разделы — латиницей |
| `неизвестный параметр «…». Может быть, «…»?` | опечатка | исправить по подсказке |
| `в источнике нет колонок: «…»` | имя колонки в `{…}` не совпадает с заголовком | сравните со строкой «колонки источника: …» в выводе проверки |
| `не похоже на дату: «…»` | дата в необычном формате | `{Дата\|date:%d/%m/%Y}` |
| `не похоже на сумму` | в колонке текст | проверьте колонку; для пустых — `{X\|money\|default:}` не нужен: пустая сумма пропускается сама |
| `ОШИБКА РАБОЧЕГО МЕСТА (HTTP 401)` | неверный или отозванный ключ | выдать новый ключ в «Сервисы и API» |
| `… (HTTP 403)` | у ключа нет нужной области | добавить область сервису (`ingest`, `export`, `calendar`) |
| `ОШИБКА СВЯЗИ … HTTP 401 (неверный логин/пароль)` | пароль внешней системы | проверьте `user` и переменную `password_env` |
| `… HTTP 404 (неверный адрес или имя объекта)` | для OData — объект не опубликован или опечатка в `entity` | откройте `…/odata/standard.odata/` в браузере |
| `нет связи: Connection refused` | сервер недоступен | адрес/порт, сеть, работает ли сервер |
| `не задана переменная окружения …` | не выполнен `секреты.bat` | запускайте через `запуск.bat` или выполните `секреты.bat` перед командой |
| `Номер … уже принадлежит делу …` (предупреждение) | тот же номер у дела с другим УИД | проверить и при необходимости слить дубли в интерфейсе |
| `календарь: … похоже на неполные данные` | в источнике не весь год | выгрузить все дни года |
| `кракозябры` в русских буквах CSV | кодировка указана неверно | уберите `encoding` (определится сама) или укажите `"cp1251"` |
| `файл не в кодировке utf-8` | в настройках `encoding`, а файл в другой | уберите `encoding` или поменяйте |
| `нет колонки «Суд.Code» (значение «Суд» не заполнено)` | в записи 1С ссылка пустая | это данные, а не настройки: заполните в 1С или добавьте `\|default:` |
| `сертификат не прошёл проверку` | HTTPS на внутреннем сертификате | `cafile = "путь/к/ca.pem"` в том же разделе |
| `адрес … без HTTPS — API-ключ передаётся открытым текстом` | `http://` в адресе рабочего места | используйте `https://` |
| `файл курсора … пустой или испорчен` | файл курсора повреждён | впишите номер последнего выгруженного события из журнала или удалите файл (тогда всё с начала) |

## 12. Рецепты

**Сумма в копейках (как в некоторых выгрузках 1С):** `claim_total = "{ЗаявленоКоп|kopecks}"`.

**Номер дела с пробелами и латинской «М»:** `aliases = "{Материал|trim|replace:M-=>М-}"`.

**Юрлицо по корпусу:**
```toml
legal_entity = "{Корпус|map:building_entity}"
[maps.building_entity]
"401" = "ГС-Саввино"
"23" = "ГС-Столичный"
"*" = ""
```

**Два решения в одном деле из одного источника** — разные `source_ref`: `source_ref = "{Ref_Key}-{ДатаРешения}"`.

**Значение из одного источника — в несколько полей:** просто перечислите поля в `[observations.fields]`
с одной и той же колонкой.

**Пробный прогон на 20 записях:** `python lawdesk_connect.py проверить мой.toml --limit 20`
(или `limit = 20` в `[connector]`).

**Переход с 1С на другую систему:** скопируйте файл настроек 1С, поменяйте `[source]` и имена колонок,
а `source` в `[observations]` оставьте прежним (`"1С"`), если новая система заменяет 1С как источник
тех же данных, — или назовите по-новому, чтобы какое-то время видеть расхождения старой и новой системы
как конфликты. Подробно — [Путь к замене 1С](замена-1с.md).

**Проверка коннектора после правок программы:** `python -m pytest connectors/tests -q` (38 автотестов,
сервер не нужен).
