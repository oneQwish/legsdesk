## 1. Что где работает

Сервер Linux с Docker, четыре контейнера (`docker-compose.yml`):

| Контейнер | Что делает | Данные |
|---|---|---|
| `db` | PostgreSQL 16 | том `pgdata` — **вся база** |
| `backend` | сервер приложения (API) | том `storage` — файлы документов; `backend/fields.toml` — справочник полей |
| `web` | nginx: интерфейс + HTTPS + прокси к API | `certs/` — сертификат |
| `backup` | ежедневные резервные копии базы и файлов ([раздел 4](#4-резервное-копирование-и-восстановление)) | том `backups` — копии |

Коннекторы работают **отдельно** — на любом компьютере, откуда видны источники (сервер 1С, рабочий ПК),
по расписанию ([коннекторы](коннекторы.md#9-запуск-по-расписанию)).

Аналогия с 1С: `db` — СУБД, `backend` — сервер 1С, `web` — веб-сервер публикации, коннекторы —
регламентные обмены.

## 2. Установка

Нужно: сервер Linux (2 ядра, 4 ГБ памяти, 50 ГБ диска на старте), Docker с Compose, DNS-имя
(например `lawdesk.company.local`), сертификат для него от внутреннего УЦ, учётная запись AD для
проверки входа не требуется (вход проверяется паролем самого пользователя).

```bash
git clone https://github.com/oneQwish/legsdesk /opt/lawdesk
cd /opt/lawdesk
cp .env.example .env
nano .env                    # пароль базы и секрет сессий (см. ниже)
nano backend/settings.toml   # AD, хранилище, часовой пояс… — раздел 6
docker compose run --rm backend python -m app.cli настройки   # проверка: «Всё в порядке.»
cp /путь/lawdesk.crt /путь/lawdesk.key certs/
docker compose up -d --build
docker compose ps            # все четыре контейнера — running (db и backend — healthy)
```

Настройки хранятся в двух местах:

| Где | Что | Кто видит |
|---|---|---|
| `.env` | только секреты: `POSTGRES_PASSWORD`, `LAWDESK_SECRET_KEY` (`python3 -c "import secrets;print(secrets.token_hex(32))"`), `LAWDESK_DOCFLOW_PASSWORD` | только сервер, в git не кладётся |
| `backend/settings.toml` | всё остальное, с пояснением у каждой строки: AD и группы ролей, хранилище, часовой пояс, защита входа, лимиты, пороги «Стола» | можно хранить в git и пересылать — паролей там нет |

При установке в `settings.toml` обязательно поправьте раздел `[ldap]` (адрес контроллера, домен, группы).
Подробно о файле — [раздел 6](#6-настройки-settingstoml).

Сервер **откажется стартовать** (текст причины — в `docker compose logs backend`), если `LAWDESK_SECRET_KEY`
короче 32 символов, если в `settings.toml` опечатка или недопустимое значение, если туда записан пароль, или если
включён режим `dev` на сервере с HTTPS.

Откройте `https://lawdesk.company.local`, войдите учёткой из группы администраторов.

> Режим `auth_mode = "dev"` (вход без пароля AD) — только для пробы на своём компьютере. Никогда на сервере.

## 3. Обновление

```bash
cd /opt/lawdesk
docker compose exec backup backup.sh now   # свежая копия перед обновлением (раздел 4)
git pull
docker compose up -d --build
docker compose logs --tail=50 backend      # нет ошибок
```
Схема базы обновляется автоматически при старте: новые таблицы создаются, а изменения существующих
выполняются из файлов `backend/migrations/*.sql` (по порядку номеров, каждый — один раз; выполненные
записаны в таблице `schema_migrations`). Если миграция не прошла, сервер не стартует, причина — в
`docker compose logs backend`, база остаётся как до этого файла. Правила — в `backend/migrations/README.txt`.

Коннекторы обновляются копированием папки `connectors` (кроме `подключения/`, `секреты.*`, `журналы/`).

## 4. Резервное копирование и восстановление

**Что копировать:** база (обязательно) и том `storage` (файлы документов, если `LAWDESK_STORAGE_BACKEND=local`).
Плюс `.env`, `certs/`, `backend/fields.toml`, `backend/settings.toml`, папка `connectors/подключения/` —
их копируйте сами при изменении (они меняются редко).

### Как это работает

Базу и файлы документов копирует контейнер **`backup`** (папка `backup/`, скрипт `backup/backup.sh`).
Cron на сервере не нужен. Каждый день в **02:30 по Москве** (`BACKUP_TIME` и `TZ` в `docker-compose.yml`) он:

1. проверяет свободное место — если меньше `BACKUP_MIN_FREE_MB` (2048 МБ), копию **не делает** и пишет ошибку;
2. делает дамп базы `pg_dump -Fc` → `db/lawdesk_ГГГГ-ММ-ДД_ЧЧММ.dump` и проверяет, что файл читается;
3. архивирует том `storage` → `storage/storage_ГГГГ-ММ-ДД.tar.gz` и проверяет архив;
4. **проверяет восстановление**: разворачивает свежий дамп во временную базу `lawdesk_restore_check`,
   сверяет число строк в таблицах `cases`, `documents`, `events` с рабочей базой и удаляет временную базу;
5. прореживает старые копии: хранятся **все за 30 дней**, по одной (последней) **на неделю за 12 недель**
   и по одной **на месяц за 12 месяцев**; самая свежая копия не удаляется никогда; если копия не
   получилась, старые не трогаются;
6. записывает итог в `status.json` — его показывает страница администратора.

Если сервер был выключен в 02:30, копия делается сразу после запуска контейнера.

Копии лежат в томе `backups` (на сервере — `/var/lib/docker/volumes/lawdesk_backups/_data`, где `lawdesk` —
имя папки проекта; точный путь: `docker volume inspect lawdesk_backups`):

```
db/lawdesk_2027-03-15_0230.dump      ← база
storage/storage_2027-03-15.tar.gz    ← файлы документов
status.json                          ← итог последней копии
```

Команды:
```bash
docker compose exec backup backup.sh now     # сделать копию сейчас (например, перед обновлением)
docker compose exec backup backup.sh check   # проверить, что последняя копия восстанавливается
docker compose exec backup backup.sh list    # список копий, что удалит прореживание, итог последней
docker compose logs --tail=50 backup         # журнал копий
```

**Статус в админке:** страница администратора берёт его из `GET /api/v1/admin/backups` (только роль admin). Тревога, если
копия с ошибкой (`ok: false`, текст в `error`), проверка восстановления не прошла (`restore_check`) или
копии не было больше 26 часов (`stale: true`).

### Копии — на другой сервер

Том `backups` лежит на том же диске, что и база: при отказе диска или сервера пропадут и копии.
Раз в сутки увозите их на другой сервер, например на резервном сервере `backup-srv` (`crontab -e`):
```
15 4 * * * rsync -a --delete-after root@lawdesk.company.local:/var/lib/docker/volumes/lawdesk_backups/_data/ /srv/lawdesk-backups/
```
(вход по SSH-ключу; `--delete-after` повторяет прореживание — уберите, если на резервном сервере хотите
хранить дольше). Копии содержат персональные данные: доступ к папке — только администраторам.

### Восстановление

Из копии базы (`.dump`) и архива файлов за одну дату:
```bash
cd /opt/lawdesk
docker compose exec backup backup.sh list                 # выбрать копию
docker compose stop backend                               # никто не должен писать в базу
# база: старые таблицы удаляются и создаются из копии
docker compose exec backup sh -c 'pg_restore --clean --if-exists --no-owner -d lawdesk /backups/db/lawdesk_2027-03-15_0230.dump'
# файлы документов (в контейнере backup том storage только для чтения — распаковываем временным контейнером)
docker run --rm -v lawdesk_storage:/data -v lawdesk_backups:/backups:ro alpine \
  sh -c 'rm -rf /data/* && tar xzf /backups/storage/storage_2027-03-15.tar.gz -C /data && chown -R 1000 /data'
docker compose start backend
docker compose logs --tail=50 backend                     # нет ошибок; открыть пару дел и документов
```
Если `pg_restore` выдал ошибки, а база уже испорчена — пересоздайте её и повторите без `--clean`:
```bash
docker compose exec db psql -U lawdesk -d postgres -c "DROP DATABASE lawdesk WITH (FORCE)" -c "CREATE DATABASE lawdesk"
docker compose exec backup sh -c 'pg_restore --no-owner -d lawdesk /backups/db/lawdesk_2027-03-15_0230.dump'
```
Копии старого вида (`.sql.gz`, до появления контейнера `backup`) восстанавливаются так:
`gunzip -c копия.sql.gz | docker compose exec -T db psql -U lawdesk lawdesk` (в пустую базу).

Проверку восстановления контейнер делает сам каждую ночь, но раз в квартал всё равно восстановите копию
на тестовом сервере целиком (база + файлы) и откройте приложение.

## 5. Пользователи и доступ

- Роль определяется **группой AD** при каждом входе: `Lawdesk-Admins` — администратор,
  `Lawdesk-Lawyers` — юрист (решает конфликты, правит сроки), `Lawdesk-Viewers` — просмотр.
  Добавить человека = включить в группу AD.
- Закрыть доступ немедленно: «Сервисы и API» → «Пользователи» → «Закрыть доступ» (или убрать из группы AD —
  действует со следующего входа; сессия живёт `[auth] session_hours` часов).
- Все действия пользователей видны в «Журнале».
- После `[auth] login_max_failures` неудачных попыток (по умолчанию 5) вход для этого логина с этого
  компьютера закрыт на `login_lockout_minutes` (15) минут — так подбор пароля не заблокирует учётную запись в AD. Перезапуск
  `backend` снимает блокировку.
- «Контроллер домена недоступен» при входе — сервер не достучался до AD (сеть, `[ldap] ldap_url`), пароль тут ни при чём.

## 6. Настройки (`settings.toml`)

Все настройки сервера — в одном файле `backend/settings.toml`, по разделам, с пояснением у каждой строки.
В файле записаны значения по умолчанию: меняйте нужное, остальное не трогайте.

| Раздел | Что настраивается |
|---|---|
| `[server]` | часовой пояс компании («сегодня» для сроков), регламентные действия |
| `[auth]` | режим входа, срок сессии, защита от подбора пароля |
| `[ldap]` | контроллер домена, домен, группы AD для ролей, таймауты |
| `[storage]` | где хранить файлы, документооборот, размер загрузки, какие файлы открываются в браузере |
| `[values]` | надёжность источников (чьё значение показывать, когда источники согласны) |
| `[deadlines]` | порог «скоро», проверка производственного календаря, запасные праздники |
| `[limits]` | размеры страниц и пакетов |
| `[tasks]` | аренда задач очереди |
| `[interface]` | «Стол»: дни ленты, пороги стопок «Горят»/«На неделю», размер стопки, цели «Моей недели», лимиты страницы «Сроки» |

**Как поменять:**
```bash
nano backend/settings.toml
docker compose run --rm backend python -m app.cli настройки   # проверка; «Всё в порядке.» — можно применять
docker compose restart backend
```
Команда `настройки` показывает итоговое значение каждой настройки и откуда оно взято: `умолчание`, `файл`
или `окружение`.

**Правила:**
- Опечатка в имени или разделе — сервер не стартует и подсказывает правильное имя («может быть, «session_hours»?»).
- Пароли и ключи в этом файле запрещены — только `.env`. Файл настроек можно хранить в git и пересылать.
- Переменная окружения `LAWDESK_<ИМЯ>` (в `.env` или `docker-compose.yml`) **главнее файла**. Если значение
  из файла «не применяется», проверьте командой `настройки`, не задано ли оно в окружении. В частности,
  `docker-compose.yml` сам задаёт `LAWDESK_COOKIE_SECURE=true` и адрес базы.
- После обновления со старой версии уберите из `.env` всё, кроме секретов (раньше настройки AD и хранилища
  задавались там) — иначе они будут главнее `settings.toml`.
- Запись: текст — в кавычках, числа и `true`/`false` — без, списки — в `[ ]`.

## 7. Поля дела (`fields.toml`)

Справочник сверяемых полей — файл `backend/fields.toml`. Каждое поле — блок:
```toml
[field.lawyer_fee]               # ключ — латиницей, навсегда (по нему поле передают коннекторы)
label = "Расходы на юриста"      # подпись — можно менять
kind = "money"                   # text | money | date | list
group = "Суммы"                  # заголовок группы в карточке дела
```
После правки: `docker compose restart backend`. Порядок блоков = порядок полей в карточке дела.

- `money` — сравнивается до копейки, попадает в «присуждено» и фильтр по суммам;
- `date` — понимает `ДД.ММ.ГГГГ` и `ГГГГ-ММ-ДД`;
- `list` — список через `;`, порядок не важен (истцы).

Не меняйте ключ существующего поля и не удаляйте поле, по которому есть данные: данные останутся, но
станут «неизвестным полем». Если поле больше не нужно — просто перестаньте его присылать.

## 8. Сервисы и API-ключи

«Сервисы и API» → «Сервисы и ключи»:
- **один сервис — одна программа/подключение** (например, `1c-ura`, `excel-reports`, `ocr-pipeline`) —
  так в журнале видно, кто что прислал;
- области — минимально нужные: загрузка — `ingest`, выгрузка — `export`, календарь — `calendar`,
  проверка коннектора — `read`;
- ключ показывается один раз; потерян — выдайте новый и отзовите старый;
- «Был в сети» показывает, когда сервис последний раз обращался — если давно, обмен не работает.

Из командной строки сервера:
```bash
docker compose exec backend python -m app.cli service excel-reports --scopes read,ingest
```

## 9. Хранилище файлов документов

- `local` — файлы в томе `storage` на сервере (по содержимому, без дублей).
- `docflow` — система документооборота через HTTP-сервис: в `settings.toml` `[storage] docflow_url`,
  `docflow_user`; пароль — `LAWDESK_DOCFLOW_PASSWORD` в `.env`. Контракт: `POST {url}/files` (multipart: `file`, `meta`) → `{"id": "…"}`;
  `GET {url}/files/{id}` → файл. Может быть реализован на 1С:Документооборот или любой другой системе.

## 10. Журналы и мониторинг

| Что | Где |
|---|---|
| Ошибки сервера | `docker compose logs --tail=200 backend` |
| Веб-сервер | `docker compose logs web` |
| Действия людей и сервисов | интерфейс → «Журнал» |
| Работа коннекторов | `connectors/подключения/журналы/<название>.log` на компьютере коннектора |
| Сервис жив? | `https://lawdesk.company.local/api/health` → `{"ok": true}`; 503 — недоступна база |
| Очередь задач | «Сервисы и API» → «Очередь задач» (проваленные — с текстом ошибки, кнопка «Повторить») |

Простой мониторинг: проверка `/api/health` раз в 5 минут в вашей системе мониторинга (Zabbix и т. п.)
и контроль кода возврата `запуск.bat` в планировщике.

## 11. Неполадки

| Симптом | Причина | Что сделать |
|---|---|---|
| Сайт не открывается | контейнер `web` или сертификат | `docker compose ps`; `docker compose logs web`; есть ли `certs/lawdesk.crt` и `.key` |
| «Неверный логин или пароль» у всех | не та настройка AD | проверить `[ldap] ldap_domain`, `ldap_base_dn` |
| «Контроллер домена недоступен» | сервер не видит AD | `[ldap] ldap_url`; доступен ли порт 636/389 с сервера |
| «Слишком много неудачных попыток» | 5 неверных паролей подряд | подождать 15 минут или `docker compose restart backend` |
| Документ скачивается, а не открывается | тип файла не PDF/картинка/текст (например HTML) | так задумано: такие файлы открываются только скачиванием ради безопасности |
| «Нет доступа: учётная запись не входит в группы» | человек не в группе AD | добавить в группу; проверить `[ldap] ldap_group_*` |
| Сервер не стартует: «Задайте LAWDESK_SECRET_KEY» | пустой секрет | заполнить в `.env` |
| Сервер не стартует: ошибка `fields.toml` | опечатка в справочнике полей | текст ошибки в `docker compose logs backend`; исправить и перезапустить |
| Сроки помечены «*» | не загружен производственный календарь года | запустить коннектор календаря |
| Конфликтов вдруг стало очень много | источник прислал значения в другом формате (копейки вместо рублей и т. п.) | в карточке дела сравнить значения источников; поправить фильтр в коннекторе (`money`/`kopecks`) и перезапустить его — значения обновятся |
| Документ не открывается («Файл отсутствует в хранилище») | файл не загружался (только карточка) или хранилище недоступно | загрузить коннектором с `file = …`; проверить `[storage] storage_backend` |
| Коннектор: HTTP 401/403 | ключ отозван / нет области | см. [коннекторы → частые ошибки](коннекторы.md#11-частые-ошибки) |
| Медленно открывается реестр | много дел, мало ресурсов | добавить памяти серверу; сообщить программисту (индексы) |

## 12. Проверка после изменений (автотесты)

Если программист что-то менял, перед установкой на сервер:
```bash
# сервер (нужен PostgreSQL для тестов, см. README)
cd backend && python -m pytest -q
# коннектор (ничего не нужно)
python -m pytest connectors/tests -q
# интерфейс собирается без ошибок
cd frontend && npm ci && npm run build
```
Все тесты должны пройти («passed», без «failed»).

На GitHub те же проверки (плюс синтаксис shell-скриптов и самопроверка прореживания копий) запускаются
сами при каждом push — `.github/workflows/ci.yml`, результат на вкладке Actions.
