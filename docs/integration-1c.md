# Интеграция с 1С (Юрайт, регламентированный календарь, Документооборот)

Решение 12.10.2026: единый источник правды — 1С. Рабочее место — место, где юрист разбирает
расхождения источников; итоговые значения уходят в 1С. Ниже — что нужно от специалиста 1С.

## 1. Итоговые значения → Юрайт

Два способа, работают одновременно:

**Файлом (сейчас).** «Сервисы и API → Выгрузка и календарь» или `GET /api/v1/export/values?format=xlsx`:

| УИД | Код суда (1С) | Суд | Номер дела | Другие номера | Юрлицо | Поле | Поле (ключ) | Значение | Статус | Кем решено | Когда | Комментарий |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

Фильтры: `status=resolved` (только решения юристов) или `resolved,confirmed`; `since=ГГГГ-ММ-ДД`; `fields=amount_debt,judge`.
Загружает файл человек (обработкой загрузки из Excel).

**Лентой изменений (для обработки 1С).** Регламентное задание 1С раз в N минут:

```
GET /api/v1/changes?after=<курсор>&actions=value_resolved
Authorization: Bearer ldk_…            (область export)
→ {"items": [{"action": "value_resolved", "case_id": 17,
              "data": {"field": "amount_debt", "after": {"value": "141611.96"},
                       "chosen": "письмо (80215024441395)", "note": "…", "sources": {…}}}, …],
   "next_cursor": 1234}
```

Реквизиты дела (УИД, суд, номер) — `GET /api/v1/cases/{case_id}`. Курсор хранить в 1С (константа/регистр).
Нужно от 1С: перечень реквизитов «Судебного дела» и соответствие ключам полей (`GET /api/v1/fields`).

## 2. Производственный календарь → сроки

Сроки по ГПК переносятся с нерабочих дней. Календарь берётся из регламентированного календаря 1С:

```
PUT /api/v1/calendar            (область calendar)
{"year": 2027, "nonworking": ["2027-01-01", "2027-01-02", …все выходные и праздники с переносами…], "source": "1С"}
```

* Год перезаписывается целиком; открытые автоматические сроки пересчитываются сразу.
* Проверка: 100–140 нерабочих дней в году (защита от неполной выгрузки).
* Пока год не загружен, используются выходные + праздники по ст. 112 ТК РФ **без** переносов, и такие сроки помечаются «*».
  Загружайте следующий год, как только Правительство утвердит переносы (обычно осенью).

## 3. 1С:Документооборот — хранилище файлов

Пока ДО не подключён, файлы лежат в томе `storage` на сервере (по sha256). Переключение — без изменения кода:

```
LAWDESK_STORAGE_BACKEND=docflow
LAWDESK_DOCFLOW_URL=https://1c.company.local/docflow/hs/lawdesk
LAWDESK_DOCFLOW_USER=…
LAWDESK_DOCFLOW_PASSWORD=…
```

Контракт HTTP-сервиса, который нужно опубликовать в ДО (минимум):

| Метод | Запрос | Ответ |
|---|---|---|
| `POST {url}/files` | multipart: `file` — содержимое, `meta` — JSON: `sha256`, `filename`, `kind`, `act_type`, `instance`, `act_date`, `track_no` | `{"id": "<идентификатор карточки>"}` |
| `GET {url}/files/{id}` | — | содержимое файла |

Идентификатор карточки сохраняется в документе (`docflow_id`) и показывается в интерфейсе.
Повторная отправка того же `sha256` должна возвращать существующую карточку (дубли по хэшу — решение 14.10).
Документы, уже лежащие в ДО, регистрируются без передачи файла: `POST /api/v1/ingest/documents` с `docflow_id` и `storage_backend: "docflow"`, `storage_ref: <id>`.

Открытые вопросы к ИТ (из журнала 14.10): версия/лицензия ДО, способ массовой загрузки, хранение `.sig` и копии с текстовым слоем, права доступа к персональным данным.
