# API: подробное описание для программистов

> Обмен с внешними системами обычно настраивается **без программирования** — коннектором
> ([коннекторы.md](коннекторы.md)). Этот документ — для тех, кто пишет код, обращающийся к API напрямую
> (Python-скрипты конвейера, будущая собственная система). Для кода на 1С — [api-для-1с.md](api-для-1с.md).

Любой скрипт конвейера (OCR, извлечение моделью, загрузчик писем, классификатор актов, ФССП…)
становится «сервисом»: он получает API-ключ и вызывает REST API. Полное описание всех методов
с примерами — интерактивно на `/api/docs` (OpenAPI).

## 1. Регистрация и ключ

В интерфейсе: **Сервисы и API → Подключить сервис**. Отметьте нужные области:

| Область | Даёт |
|---|---|
| `read` | чтение дел, документов, сроков |
| `ingest` | загрузка дел, наблюдений по полям, документов и файлов |
| `tasks` | очередь задач: создать, захватить, продлить, завершить |
| `export` | лента изменений `/changes` и выгрузка для 1С |
| `calendar` | загрузка производственного календаря |

Ключ показывается один раз. Передавайте его в заголовке:

```
Authorization: Bearer ldk_<prefix>_<secret>
```

Из командной строки сервера: `python -m app.cli service ИМЯ --scopes read,ingest --task-types ocr`.

## 2. Клиент

`connectors/lawdesk_client.py` — один файл, только стандартная библиотека. Скопируйте рядом со своим скриптом:

```python
from lawdesk_client import Lawdesk
ld = Lawdesk("https://lawdesk.company.local", key=os.environ["LAWDESK_KEY"], cafile="company-ca.pem")
```

## 3. Как указывать дело

Везде, где нужно дело, подходит любой из ключей (по приоритету):

```json
{"case_id": 123}
{"uid": "50RS0010-01-2025-000287-27"}
{"court_code": "000000123", "case_number": "2-1459/2025"}     // номер — основной или любой псевдоним (М-…, прежний 2-…)
```

`court_code` — код суда в справочнике 1С (как в `court_map` sot.db).

## 4. Дела — `POST /api/v1/ingest/cases`

```python
ld.cases([{
    "uid": "50RS0010-01-2025-000287-27",
    "court_code": "000000123", "court_name": "Железнодорожный городской суд Московской области",
    "case_number": "2-1459/2025", "aliases": ["М-257/2025"],
    "legal_entity": "ГС-Саввино", "complex": "ЖК Героев", "building": "401", "flat": "214",
    "contract_no": "АВТ401-02-12-04-214", "plaintiffs": "Иванов И.И.; Петрова А.А.",
    "appeal_flag": False,
}])
# → [{"index": 0, "ok": true, "case_id": 17, "created": true, "warnings": []}]
```

Правила: поиск по УИД, затем по суду + любому номеру. Если номер уже принадлежит делу **с другим УИД**,
создаётся новое дело, а в `warnings` будет предупреждение (номер не уникален между УИД). Второй УИД для
того же дела не перезаписывает первый — он сохраняется как «спорный» (`extra.other_uids`).
Слить дубли может юрист в карточке дела.

## 5. Значения полей — `POST /api/v1/ingest/observations`

Каждый источник сообщает **своё** значение поля, с доказательством:

```python
ld.observations([{
    "uid": "50RS0010-01-2025-000287-27",
    "field": "amount_debt",          # ключи полей: GET /api/v1/fields
    "source": "письмо",              # 1С | отчёт | OCR | письмо | …
    "source_ref": "80215024441395",  # ключ записи в источнике: трек, строка выгрузки, id документа
    "value": "141611.96",
    "document_sha256": "…",          # документ, из которого взято (если уже загружен)
    "page": 4,
    "quote": "взыскать … 141 611 (сто сорок одна тысяча …) рублей 96 копеек",
}])
# → [{"ok": true, "observation_id": 9, "case_id": 17, "field": "amount_debt", "status": "confirmed"}]
```

* Пара `source` + `source_ref` идентифицирует наблюдение: повторная отправка обновляет его, а не дублирует.
* Значения сравниваются после приведения: суммы — до копейки (`141 611,96 руб.` = `141611.96`), даты — `ДД.ММ.ГГГГ` = `ГГГГ-ММ-ДД`,
  текст — без регистра, кавычек, лишних пробелов, `ё`=`е`; списки (истцы через `;`) — без учёта порядка.
* Поля сумм: `amount_debt`, `amount_penalty`, `amount_fine`, `amount_moral`, `amount_expertise`, `amount_postal`,
  `amount_representative`, `amount_duty`, `claim_total`. Неизвестное поле принимается как текстовое.

## 6. Документы

Только метаданные (файл остаётся у источника или уже лежит в 1С:ДО):

```python
ld.documents([{
    "sha256": "…", "filename": "решение.pdf", "kind": "письмо",
    "act_type": "решение", "instance": "первая",
    "act_date": "2026-09-01", "motivated_date": "2026-09-08",   # от motivated_date считается апелляция
    "track_no": "80215024441395",
    "text": "…цифровой текст…", "text_source": "цифровой",
    "case": {"uid": "50RS0010-01-2025-000287-27"},
    "storage_backend": "external",
}])
```

С файлом (попадёт в хранилище; sha256 считается на сервере):

```python
ld.upload("письма_оригиналы/pdf/80215024441395.pdf",
          meta={"kind": "письмо", "act_type": "решение", "act_date": "2026-09-01",
                "case": {"uid": "…"}},
          signature="письма_оригиналы/sig/80215024441395.sig")
```

Виды актов, от которых считаются сроки: `решение`, `дополнительное решение`, `заочное решение`
(для отмены заочного — `meta.delivered_date`), `апелляционное определение`, любое `определение…`
(частная жалоба). Если указанного дела нет — документ сохраняется непривязанным, ссылка — в `meta.unresolved_case_ref`.

## 7. Очередь задач

Задачи создают юристы (кнопками в интерфейсе — в следующих версиях) и сервисы: `POST /api/v1/tasks`.
Исполнитель забирает задачи своих типов:

```python
def handle(task):
    path = task.payload["path"]
    pages = recognize(path)          # долгая работа: task.heartbeat() продлевает аренду
    return {"pages": pages}          # → complete; исключение → fail с повтором через 60 с

ld.run(handle, types=["ocr"])       # бесконечный цикл; stop_when_empty=True — до опустошения очереди
```

Гарантии: одну задачу не получат два исполнителя; если исполнитель упал и не продлил аренду
(по умолчанию 600 с), задача вернётся в очередь; после `max_attempts` — статус `failed`, видна в разделе «Очередь задач».

## 8. Лента изменений — `GET /api/v1/changes`

Для сервисов, которым нужно реагировать на действия юристов (интеграция с 1С, пересчёт в sot.db):

```python
for ev in ld.follow_changes("cursor.txt", actions="value_resolved,case_merged,document_linked"):
    apply(ev)    # ev["data"]: field, before, after, chosen, note, sources
```

Курсор (`next_cursor`) монотонный, события идут в порядке фиксации, пропусков нет — сохраните курсор после обработки.

## 9. Ошибки

* Пакетные методы отвечают `200` и списком результатов по элементам (`ok`, `error`) — ошибка одного не откатывает остальные.
* `401` — нет/отозван ключ; `403` — нет нужной области; `413` — больше 1000 элементов в запросе; `503` — хранилище файлов недоступно.
