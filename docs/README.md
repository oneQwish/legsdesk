# Документация рабочего места юриста

Документация написана для команды, где основные специалисты — разработчики 1С. Python и веб-разработку
знать не нужно: почти всё обслуживание — это правка текстовых файлов настроек и запуск готовых команд.
Там, где без программиста не обойтись, это сказано прямо.

## Что можно делать без программиста

- подключать источники и приёмники данных — файлами `*.toml` ([коннекторы](коннекторы.md));
- добавлять и переименовывать поля дела — файлом `backend/fields.toml`;
- выдавать и отзывать ключи сервисов, управлять доступом пользователей — в интерфейсе («Сервисы и API»);
- обновлять систему, делать резервные копии, смотреть журналы — по [инструкции](администрирование.md);
- писать на 1С всё, что обменивается с рабочим местом, — по [примерам](api-для-1с.md).

## Что требует программиста (Python / TypeScript)

- новая страница или новый элемент интерфейса;
- новый вид процессуального срока или правило его расчёта (`backend/app/deadlines.py`);
- новый *тип* источника данных, которого нет в списке (сейчас есть: csv, xlsx, json, папка с файлами,
  HTTP/JSON, OData, SQLite, любая СУБД через SQL) — но сначала проверьте, нельзя ли выгрузить данные в один из них.

## Карта репозитория

```
backend/            сервер (Python): API, база данных, расчёт сроков
  fields.toml       ← справочник полей дела (правится без программиста)
  app/              код сервера
  tests/            автотесты сервера
frontend/           интерфейс (React/TypeScript)
connectors/         коннекторы — обмен данными с другими системами
  lawdesk_connect.py   универсальный коннектор (один файл)
  примеры/             заготовки настроек под каждый тип источника, с комментариями
  подключения/         ваши рабочие настройки — их выполняет запуск.bat / запуск.sh
  tests/               автотесты коннектора
docs/               эта документация
docker-compose.yml  запуск на сервере
.env.example        образец настроек сервера
```
