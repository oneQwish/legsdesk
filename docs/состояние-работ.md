# Состояние работ

Короткий журнал решений и состояния проекта — чтобы продолжить с любого места.
Подробности по каждой части — в остальных документах `docs/`.

## Обновлено: 22.10.2026 (после аудита)

## Решения заказчика (согласованы)

| Вопрос | Решение |
|---|---|
| Стек | FastAPI + PostgreSQL + React (TypeScript, Vite) |
| Где работает | сервер в сети компании (Docker Compose: db, backend, web/nginx с HTTPS) |
| Вход | доменная учётка AD/LDAP, роли по группам: admin / lawyer / viewer |
| Данные от конвейера | своя БД; сервисы шлют через API; коннекторы читают источники (в т.ч. sot.db) только на чтение |
| Интеграция сервисов | REST + API-ключи с областями (read, ingest, tasks, export, calendar) + очередь задач |
| Конфликты | решает один юрист; своё значение — только с комментарием |
| Персональные данные | всем ролям без маски |
| Производственный календарь | загружается из 1С (или файла) коннектором; без него — ст. 112 ТК без переносов, срок помечается «*» |
| Хранилище файлов | цель — 1С:Документооборот; сейчас адаптер: `local` (по sha256) / `docflow` (заготовка HTTP-контракта) |
| Решения юристов → внешние системы | журнал + лента изменений с курсором + выгрузка XLSX/CSV + коннектор `out` |
| Коннекторы | **не только под 1С**: продукт может в будущем заменить 1С; сопровождают одинэсники без Python → настройки `.toml`, подробная документация на русском |
| Интерфейс | узкая полоса иконок; «Стол» со стопками карточек (листать / разложить пасьянсом); тёмная «бумажная» тема (слоновая кость, чернила, сургуч, малахит, PT Serif); «компактно, но с воздухом»; переключатель «Карточки / Таблица» |
| Фильтры | максимум фильтров, фасеты со счётчиками, подборки (личные, выкладываются стопкой на стол); фильтр по судье — по любому источнику |
| Визуальные приёмы (выбраны) | лента дней на 2 недели; «чистый стол» + серия дней без просрочек; «моя неделя» с целями; командная палитра Ctrl+K; путь дела (этапы); хронология дела; присуждено от заявленного |
| Репозиторий | github.com/oneQwish/legsdesk, ветка main (**публичный** — рекомендовано сделать приватным; в репозитории только код и демо-данные) |

## Что сделано (по коммитам)

1. Бэкенд: дела (УИД + псевдонимы номеров), значения по источникам и статусы, решения/переоткрытие, слияние дублей, документы (загрузка, хранилище), сроки ГПК (321, 209, 237, 376.1, 332, 107–108), календарь, очередь задач (SKIP LOCKED, аренда), журнал = лента изменений (номер ленты присваивается при чтении под advisory-lock), выгрузка XLSX/CSV, AD/dev-вход, API-ключи.
2. Интерфейс React + коннекторы sot.db и Python-клиент, Docker, первая документация.
3. Новый интерфейс: стол со стопками, бумажная тема, узкая навигация, окна вместо prompt, уведомления.
4. Фильтры: общий `CaseFilter` для /cases, /conflicts, /deadlines; фасеты `/cases/facets`; подборки `saved_views`.
5. Фильтр по судье (по наблюдениям источников, без учёта регистра и «ё»).
6. Визуальные приёмы: `/desk/strip`, `/desk/progress`, awarded/claimed в списке дел, путь дела, хронология, палитра.
7. Универсальный коннектор `connectors/lawdesk_connect.py` (+12 заготовок), `backend/fields.toml`, документация `docs/`.
8. Аудит 22.10.2026 (три коммита «Аудит …»):
   - **сервер:** закрыты чтение любых файлов сервера через встроенную раздачу интерфейса (`..%2f`) и выполнение
     HTML/скрипта из загруженного «скана»; лимит загрузки; защита входа от перебора; «сегодня» по
     `LAWDESK_TIMEZONE`; миграции `backend/migrations/*.sql`; индексы; проверка опасных настроек при старте;
     `/api/health` проверяет базу;
   - **коннекторы:** атомарный курсор, выгрузка порциями, замок от двойного запуска, повторы с паузами,
     дробление пакета при ошибке формата, номера строк в ошибках, cp1251, коды возврата 0–5;
   - **интерфейс:** гонки запросов, «прошлое дело» при переходе, необработанные ошибки, двойные отправки,
     истёкшая сессия без потери черновика, доступность с клавиатуры, кэш повторных запросов.

Тесты: сервер — 26 (`backend/tests`, нужен PostgreSQL), коннектор — 48 (`connectors/tests`, без сервера).

## Открытые вопросы и следующие шаги

Согласованный план этапов — [план-развития.md](план-развития.md).

- **Проверить на реальных данных:** коннектор на настоящей sot.db (`примеры/sqlite_sot.toml` написан по описанию схемы — сверить колонки), OData/HTTP-сервис реальной 1С, вход через реальный AD, сборка Docker-образов (в среде разработки Docker-демона не было).
- **Код 1С в `docs/api-для-1с.md`** не запускался в реальной базе — имена объектов заменить на свои.
- **«Заявлено»** нужно присылать из 1С (поле `claim_total`) — иначе нет процента «присуждено от заявленного».
- **Исполнение (ФССП)**: этап пути дела отмечается по документам `kind = "ФССП"` — нужен источник таких документов.
- **Для этапа «замена 1С»** (см. `замена-1с.md`): создание и свободная правка дела в интерфейсе, справочники судов/юрлиц, права по юрлицам, поручения, учёт ИП, печатные формы.
- Порядок/переименование подборок в интерфейсе (через API уже можно).
- Миграции схемы БД: сделаны простым механизмом SQL-файлов (`backend/migrations`, см. README.txt там).
- Остаток аудита (не критично): блокировка входа хранится в памяти процесса (при нескольких экземплярах
  сервера — у каждого своя); вкладки «Хронология» и «Журнал» дела загружают события дважды; нет сводного
  запроса для «Стола» (7 запросов списка дел при загрузке); полноценная навигация стрелками в палитре для
  экранных чтецов (role=listbox).
